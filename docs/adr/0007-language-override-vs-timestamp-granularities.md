# Segment timestamps and diarization take priority over a manual language override

Mistral's API documentation states that `timestamp_granularities` is not compatible with `language` on the same request. Per-segment start/end timestamps and diarization are load-bearing for the whole feature — they drive every subtitle cue boundary and the speaker-change labeling — while the manual French/English override is a secondary accuracy nicety on top of auto-detection. So when a user picks a language explicitly, the client first tries the request with both `language` and `timestamp_granularities`; if Mistral rejects that combination, it retries once with `timestamp_granularities` kept and `language` dropped (silently falling back to auto-detect for that run) rather than losing segment timing. The alternative — honoring the language override and losing segment timestamps — was rejected because it would silently break cue splitting and speaker labeling, a much larger regression than an ignored language hint.

Confirm at implementation time whether the two fields are actually mutually exclusive in practice (the retry path is a no-op if they aren't); this ADR records the priority order regardless of that outcome.
